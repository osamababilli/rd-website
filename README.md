# موقع RD Group

موقع وكالة RD Group مبني من تصميم «RD Group — Website»: ثلاث لغات (العربية RTL، الإنجليزية، التركية)، وضع داكن وفاتح، و7 صفحات.

## التشغيل

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # بناء نسخة الإنتاج
npm start          # تشغيل نسخة الإنتاج
```

انسخ `.env.example` إلى `.env.local` واملأ القيم قبل النشر.

## التقنيات

| الجزء | التقنية |
| --- | --- |
| الإطار | Next.js 16 (App Router) + React 19 + TypeScript |

| لوحة التحكم | `/admin` بالعربية، قاعدة بيانات SQLite (`better-sqlite3`)، دخول بكلمة مرور واحدة |
| SEO | عناوين ووصف لكل لغة، canonical و hreflang، `sitemap.xml` و`robots.txt` |
| النشر | خادم Node.js بقرص دائم (VPS، Railway، Render، Docker…) لأن SQLite ملف على القرص |

## لوحة التحكم (`/admin`)

- **نظرة عامة:** عدد الطلبات الجديدة وآخر 30 يوماً وأحدث الطلبات.
- **طلبات العملاء:** كل طلب من نموذج الرئيسية أو صفحة التواصل يُحفظ هنا. بحث، وتصفية حسب الحالة (جديد، تم التواصل، تم الاتفاق، مغلق)، وصفحة لكل طلب فيها أزرار بريد وواتساب واتصال، وملاحظات داخلية، وحذف.
- **إعدادات الموقع:** الهاتف وواتساب والبريد ورابط الخريطة، والعنوان وساعات العمل بثلاث لغات، وأرقام الصفحة الرئيسية، وروابط التواصل الاجتماعي. يظهر التعديل على كل صفحات الموقع فور الحفظ.

الدخول بكلمة المرور `ADMIN_PASSWORD` من `.env.local`. قاعدة البيانات ملف `data/rd-group.db` يُنشأ تلقائياً (غير مرفوع على git). **انسخه احتياطياً بانتظام**، فهو يحوي طلبات العملاء.

> لا تنشر على Vercel أو أي استضافة Serverless: ملف SQLite لا يبقى بين الطلبات هناك. استخدم خادماً بقرص دائم، أو اضبط `DATABASE_PATH` على مسار قرص دائم.

## أين أعدّل المحتوى

- **النصوص:** `src/i18n/dictionaries/ar.ts` و`en.ts` و`tr.ts` (TypeScript يمنع نسيان أي نص في أي لغة).
- **بيانات التواصل والروابط الاجتماعية وأرقام الرئيسية:** من لوحة التحكم ← إعدادات الموقع.
- **المشاريع وأدوات كل خدمة:** `src/content/data.ts`.
- **الألوان والمسافات:** أعلى `src/app/globals.css`.
- **الشعار:** الشارة الدائرية في `src/assets/rd-badge.png` (مقصوصة من الشعار الأصلي)، والشعار الكامل بنسختيه في `public/brand/`. أيقونة المتصفح `src/app/icon.png` وصورة المشاركة `src/app/opengraph-image.png` مولّدتان منه.

### إضافة دراسة حالة

1. أضف الـ slug إلى `CASE_STUDY_SLUGS` في `src/content/data.ts`.
2. أضف محتواها تحت `caseStudies` في القواميس الثلاثة.
3. أضف فئاتها إلى `META` في `src/app/[locale]/work/[slug]/page.tsx`.

بطاقات المشاريع التي ليس لها دراسة حالة تظهر بلا رابط.

## قبل الإطلاق

النصوص بين قوسين مربعين `[...]` أماكن مخصّصة من التصميم ويجب استبدالها:

- **من لوحة التحكم:** الهاتف وواتساب والبريد والعنوان وساعات العمل ورابط الخريطة وأرقام الرئيسية (250+ و120+ و8+ و12+ قيم تجريبية) وروابط التواصل الاجتماعي.
- أسماء العملاء وشهاداتهم، وشعارات «يثق بنا» (CLIENT 01…06).
- نتائج دراسة الحالة، وصور وأسماء الفريق، وسنة التأسيس.
- نص سياسة الخصوصية والشروط (مهم قانونياً لأن الموقع يجمع بيانات عبر النماذج — KVKK/GDPR).
- ضبط `ADMIN_PASSWORD` و`ADMIN_SECRET` على الخادم (كلمة مرور قوية وسلسلة عشوائية طويلة).

### إعداد البريد (SMTP)

ضع بيانات حساب البريد في `.env.local` (أو متغيرات البيئة على الاستضافة):

| المتغير | المعنى |
| --- | --- |
| `SMTP_HOST` | خادم البريد، مثل `mail.rdgrouptr.com` أو `smtp.gmail.com` |
| `SMTP_PORT` | `465` (SSL/TLS) أو `587` (STARTTLS) |
| `SMTP_USER` / `SMTP_PASS` | بريد الحساب وكلمة مروره (في Gmail استخدم «كلمة مرور التطبيقات») |
| `CONTACT_TO_EMAIL` | البريد الذي تصله الطلبات (يمكن عدة عناوين بفاصلة) |
| `CONTACT_FROM_EMAIL` | اسم وعنوان المرسل؛ غالباً يجب أن يطابق `SMTP_USER` |

يُضبط `Reply-To` على بريد العميل، فالردّ من بريدك يذهب إليه مباشرة.

البريد اختياري: كل طلب يُحفظ في لوحة التحكم حتى بدون SMTP. يظهر للزائر خطأ فقط إذا تعذّر الحفظ والإرسال معاً.
